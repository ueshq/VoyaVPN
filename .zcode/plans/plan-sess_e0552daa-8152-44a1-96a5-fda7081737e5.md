# 让主页记住出口 IP 检测结果

## 根因

- 出口 IP 检测结果只存在 TanStack Query 缓存里，key 为 `["connection-ip", "profileId:mainPid"]`（`apps/desktop/src/ipc/query-keys.ts:56`）。
- `apps/desktop/src/features/home/use-connection-ip.ts:26` 设置了 `gcTime: 0`；而页面切换是条件渲染（`app-shell.tsx` 一次只挂载当前屏幕），离开主页的瞬间观察者归零，缓存被立即垃圾回收。
- 返回主页后查询以空状态重新挂载，`enabled` 默认为 false（`autoCheckIp` 默认关闭），不重查 → 回退显示 `home.checkIpNotChecked`「未检测」。

## 方案：让查询缓存跨挂载存活（最小改动）

查询 key 已按连接（`profileId:mainPid`）编码，连接一换 key 即变、旧结果自然不可见；`staleTime: Infinity` 也已设置。唯一缺的就是缓存存活时间。

1. **`apps/desktop/src/features/home/use-connection-ip.ts`**
   - `gcTime: 0` → `gcTime: Number.POSITIVE_INFINITY`。
   - 更新第 8–11 行的文档注释：结果在同一连接内跨页面切换保留（回到主页直接命中缓存、不重发探测），但仍随所属连接结束而失效（重连后 pid 变化 → 新 key → 恢复「未检测」，这是正确语义：新连接的出口 IP 可能不同）。
   - 内存影响：`gcTime: Infinity` 会为每次连接保留一条极小的缓存条目（`{ip, countryCode}`），上界为本次会话的重连次数，可忽略。

2. **回归测试：`apps/desktop/src/features/home/exit-ip-metric.test.tsx`**
   - 新增用例：连接状态下点击检测显示 `203.0.113.9 · JP` → `view.unmount()` → 用**同一个** `queryClient`（`renderWithQuery` 已支持传入）重新渲染 → 仍显示该地址，且 `checkConnectionIp` 没有被再次调用（证明命中缓存而非重新查询）。

### 行为变化说明

- 同一连接内切页返回：显示已记住的 IP（含世界地图 marker，`home-screen.tsx:85` 共用此查询，一并受益）。
- 断开/重连（pid 变化）：恢复「未检测」——沿用现有设计意图（"a result never outlives the connection it describes"），避免展示过期 IP。
- `autoCheckIp` 开启的用户：返回主页命中缓存而不是再发一次探测（减少冗余请求）；重连后仍会自动检测。
- 失败状态同样跨页保留，「点击重试」仍会强制 refetch，行为不变。

### 不采用的备选

- 仿测速结果放入模块级 Zustand store：改动面大，且查询 key 已表达连接作用域，属于重复实现。
- 后端缓存/持久化到 localStorage：出口 IP 是按连接的瞬态数据，跨启动保留会展示陈旧结果。
