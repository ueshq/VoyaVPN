## 根因

点击连接（TUN 模式）后，PacketTunnel 扩展启动 sing-box 报：
`parse rule-set[0]: open .../app.voyavpn.desktop/bin/srss/geoip-cn.srs: operation not permitted`

不是路径拼接 bug（目录本来叫 `bin/srss`）。真实原因：voya-core 生成配置时把本地规则集写成 `type: local` + 主 app 沙盒容器内的**绝对路径**（`crates/voya-core/src/singbox/experimental.rs:113` `ruleset_for_tag`，路径来自 `crates/voya-app/src/updates.rs:63` 扫描 `bin/srss`）。`macos_packet_tunnel_bridge.m` 的 `VoyaCreateRuntimeConfigData` 把该 JSON 原样嵌入 app group 里的 `packet-tunnel-runtime.json`；PacketTunnel 扩展（独立沙盒 `app.voyavpn.desktop.PacketTunnel`）对主 app 容器无读权限 → EPERM。

## 修复：在主 app 侧桥接层把 .srs 暂存进 app group 并改写路径

主 app 进程是唯一同时拥有「主容器读权限 + app group 写权限」的一方，因此在 `crates/voya-platform/native/macos_packet_tunnel_bridge.m` 的 `VoyaCreateRuntimeConfigData`（约 356-402 行）中处理：

1. 读入 sing-box 配置 JSON 后用 `NSJSONSerialization` 解析为字典。
2. 遍历 `route.rule_set[]`：对 `type == "local"` 且 `path` 为绝对路径的条目：
   - 在 app group 容器下创建子目录（如 `srss/`），把源 `.srs` 文件复制过去（覆盖旧文件）；
   - 将该条目的 `path` 改写为 app group 容器内的绝对路径。
3. 用改写后的 JSON 重新序列化放入 `singboxConfigJson`；复制失败则返回明确错误（提示哪个文件暂存失败）。
4. 复用现有 `VoyaAppGroupURL` 帮助函数；对 `cache.db` 等相对路径不做处理（扩展已在其工作目录解析，之前一直可用）。

不改 voya-core / Rust 侧：核心层无法感知 app group 路径，且非 TUN 的主进程配置用本地路径是对的。
