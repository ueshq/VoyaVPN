# 清理计划：冗余间接层、重复实现与死代码（可维护性优先）

按依赖顺序分 4 个工作包执行，每包完成后跑针对性检查，最后跑完整 `pnpm run verify:local`。所有发现均已逐条验证过调用点。

## WP1 — voya-core / voya-db 去重

1. **移除恒真协议门**（`singbox_supports_config_type` 恒 true，11/11 协议支持）：
   - 删 `crates/voya-core/src/singbox/support.rs:44-63` 的函数
   - 删 `context/validation.rs:14-18` 死分支、core 侧 `ValidationCode::UnsupportedProtocol` 变体
   - 删 `singbox/routing.rs:421-423` 死分支
   - 删 `singbox/tests.rs` 中恒假的 `expected_rejection` 断言
   - 连锁：`voya-contracts/src/messages.rs` 的 `ValidationCode::UnsupportedProtocol` → `voya-app/src/contract_map/messages.rs` 映射与穷举测试 → locale key → 前端错误码注册
   - 跑 `pnpm generate:bindings` 重生成 bindings.ts 并纳入变更
2. **删除 Voya bundle 导入路径**（导出已于 e1ee77e 移除，无生产者）：删 `fmt/entry.rs:165-212`（`VoyaBundleProfile` 单变体枚举 + `parse_voya_profile_bundle`）、`fmt/tests.rs` 相关测试、`voya-app/src/subscriptions/manager/parse.rs:67` 调用分支
3. **内联 `protocol_name`**（`protocol_common.rs:13-27`，与 `as_str` 仅 WireGuard 拼写不同）：2 个调用点改 `as_str().to_ascii_lowercase()`，删表
4. **合并三个逗号 splitter**（`split_list`/`split_csv`/`first_list_value`，trim 语义各异）：一个 canonical trim-split + Option 薄包装，替换 ~9 个调用点；逐点核对语义，golden 测试守护
5. **voya-db 去重**：`executor.rs` 增加 `max_sort(table)`/`exists(table, id)` 助手（挨着既有 `delete_each`），替换 4 份 `max_sort` + 3 份 `exists` 手写体
6. **小项**：URI 构建中间层 `to_uri_without_scheme` 折叠（url_encode 内联进 hysteria2 调用点）；nonempty 家族合并到 `text.rs`；`protocol_share` 的 HTTP 通配臂改显式分支；`context.rs` 的 `is_domain`/`validate_node` 降为 `pub(crate)`

## WP2 — voya-app 死代码与重复

1. **删 5 个仅测试调用的 pub 方法**并改写测试调用点：
   - `SubscriptionManager::update_subscriptions`（6 个测试点 → 显式 prepare+apply 两步）
   - `SpeedtestManager::run`（11 处 → `run_with_callback(.., |_| {})`）
   - `TunManager::set_enabled`（7 处 → `plan_set_enabled` + `apply_enabled`）
   - `SystemProxyManager::status`（全仓库零调用，直接删）
   - `AppServices::load_config`（4 处 → `load_config_for(_, None)`）
2. **删 `RuntimeManager::restart`**（与 `connect` 逐字相同）：`CoreFlow::restart` 改调 `connect`，保留 Restarting/Restarted 日志码差异；追查 `SupervisorCommand::Restart`/`CoreSupervisor::restart` 可达性，不可达则一并删
3. **退避统一**：`backoff.rs` 增加 `exponential_delay(attempt, initial, max) -> Duration`，替换 `supervisor/crash.rs`、`subscriptions/auto_update.rs`、`speedtest/manager.rs` 三份重复体（保留各自 jitter/首试为零的差异并显式化）；`unix_now_seconds` 两处定义合一
4. **ID 生成统一**：profiles/routing/subscriptions 三处手写 nanos^counter^pid 生成器 → `Uuid::new_v4().simple()`（与 policy_groups 现状一致）；先确认无测试/消费方依赖 ID 格式

1. **`apply_config_change` 组合器**（mutate → emit invalidation → restart_after_config_change）：收编 7 个 routing 命令的重复 4 步脚手架、`tray_activate_node/group`、`set_active_profile`、`set_active_policy_group`（共 ~11 处）；保留命令返回 Result / tray 走 `report_tray_failure` 的错误策略差异
2. **`apply_config_removal` 组合器**（mutate → emit invalidation → `disconnect_removed_profile`）：收编 `delete_profiles`、`delete_subscriptions`、`import_profiles_from_text`、`update_subscriptions` 命令尾部与 auto_update sink 的重复尾部（~6 处）
3. **不合并** MoveAction 两套 index 映射（profiles 元素索引 vs routing 插入位置语义）——故意的不同契约
